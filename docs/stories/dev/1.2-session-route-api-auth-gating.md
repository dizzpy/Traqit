# Story 1.2: Session Route Api Auth Gating — Auth & Authorization

## Story

As a security-conscious product owner,
I want every route and API call to be gated by a verified session,
so that no page or endpoint is reachable without proper authentication.

## Acceptance Criteria

1. Given no active session, when a user requests any `/app/*` page, then they are redirected to `/login`.
2. Given no active session, when a client calls any `/api/*` route, then the response is 401.
3. Given a valid session, when the middleware runs, then the verified user id is forwarded via `x-auth-user-id`, and any client-supplied copy of that header is stripped first.
