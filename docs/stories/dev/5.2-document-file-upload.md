# Story 5.2: Document File Upload — Documents

## Story

As a job seeker,
I want to upload a file (CV, image, or other) instead of only pasting a link,
so that I can attach my actual documents without needing them hosted elsewhere first.

**Status:** ✅ Implemented on `fix/storie-issues` (2026-10-07), awaiting QA.
**SRS:** FR-5.2 in `docs/srs.md`

## Acceptance Criteria

1. Given the Documents tab, when I choose 'Upload file' instead of 'Link', then I can select and upload a file from my device.
2. Given a file over the size limit or of an unsupported type, when I attempt to upload it, then I get a clear rejection message and no partial record is created.
3. Given a successfully uploaded document, when I open it, then it downloads/opens correctly.
4. Given I delete an uploaded document, when confirmed, then the underlying file is also removed from storage, not just the DB row.

## Implementation Notes

- Limits: 10 MB; PDF, DOCX, PNG, JPG. Checked in the browser and on the server.
- Private `documents` bucket with no RLS policies; all access goes through `src/lib/storage.ts` using the service-role client. Paths are `{profileId}/{applicationId}/{uuid}-{filename}`.
- A document's URL is the internal `/download` route, which checks ownership and redirects to a 60-second signed URL.
- The file is uploaded before the DB row is created; if the row write fails, the file is removed.
- SQL: `prisma/sql/add_document_upload_fields.sql`, `prisma/sql/create_documents_storage_bucket.sql`. **Run both on every other environment before deploy.**
