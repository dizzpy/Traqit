# Story 5.2: Document File Upload — Documents

## Story

As a job seeker,
I want to upload a file (CV, image, or other) instead of only pasting a link,
so that I can attach my actual documents without needing them hosted elsewhere first.

**Status:** ❌ Not started — verified against code on `main`, no implementation found.

## Acceptance Criteria

1. Given the Documents tab, when I choose 'Upload file' instead of 'Link', then I can select and upload a file from my device.
2. Given a file over the size limit or of an unsupported type, when I attempt to upload it, then I get a clear rejection message and no partial record is created.
3. Given a successfully uploaded document, when I open it, then it downloads/opens correctly.
4. Given I delete an uploaded document, when confirmed, then the underlying file is also removed from storage, not just the DB row.

## Tasks / Subtasks

- [ ] Storage setup
  - [ ] Create a Supabase Storage bucket scoped per-profile path (e.g. `documents/{profileId}/{applicationId}/{filename}`)
  - [ ] Configure bucket access so one user cannot read another's files
- [ ] Upload UI
  - [ ] Add 'Link' vs 'Upload file' mode toggle to the document form
  - [ ] Client-side size/type validation before upload attempt
- [ ] API
  - [ ] Add upload handling to document create route
  - [ ] Store storage path/reference in `Document` row, not raw file
  - [ ] On delete, remove the file from storage, not just the DB row
