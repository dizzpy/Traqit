# Story 16.1: Husky Lint Staged Pre Commit Pre Push — CI/CD & Tooling

## Story

As a developer working on this codebase,
I want lint/format to run automatically before commit, and typecheck before push,
so that obviously broken code never gets committed or pushed in the first place.

**Status:** ✅ Implemented on `fix/storie-issues` (2026-10-07), awaiting QA.
**SRS:** NFR-MAINT-1 in `docs/srs.md`

## Acceptance Criteria

1. Given a commit with a lint/format violation in staged files, when I attempt to commit, then the commit is blocked until fixed (or auto-fixed by lint-staged where possible).
2. Given a push with a TypeScript error, when I attempt to push, then the push is blocked.

## Tasks / Subtasks

- [x] Setup
  - [x] Install and configure Husky + lint-staged
  - [x] Pre-commit hook: run lint-staged (eslint --fix + format on staged files)
  - [x] Pre-push hook: run `tsc --noEmit`

### Architecture Compliance

- Local-only enforcement; does not replace CI, just catches issues earlier for the developer.

### Testing Requirements

- Attempt to commit a file with a lint error, confirm it's blocked/fixed.
- Attempt to push with a type error, confirm it's blocked.

## Implementation Notes

- Husky + lint-staged + Prettier. Pre-commit: `eslint --fix` and `prettier --write` on staged files. Pre-push: `bun run typecheck`.
- New scripts: `typecheck`, `format`, `format:check`. `.prettierrc.json` is `{}` (defaults already match the codebase).
