# Story 15.1: Fix Open Redirect Auth Callback — Reliability & Defect Fixes

## Story

As a security-conscious product owner,
I want the auth callback's redirect target to be validated,
so that an attacker cannot craft a magic-link URL that redirects a victim to a malicious site.

## Acceptance Criteria

1. Given a `next` query param that is an absolute URL to another host, when the callback processes it, then the redirect is rejected or defaulted to a safe internal path, not followed.
2. Given a `next` query param that is a normal relative path, when the callback processes it, then it works exactly as before.

## Tasks / Subtasks

- [ ] Fix validation
  - [ ] In `src/lib/urls.ts`, change `appPath()` from a pure passthrough to reject anything not starting with a single `/`
  - [ ] Add a regression test or manual check for `?next=https://evil.com`
