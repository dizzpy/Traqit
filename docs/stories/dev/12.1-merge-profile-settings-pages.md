# Story 12.1: Merge Profile Settings Pages — Settings, Profile & Notifications

## Story

As a user confused by two overlapping preference pages,
I want one single Settings page instead of duplicate Profile and Settings pages,
so that I'm not unsure which page is authoritative for my preferences.

**Status:** ✅ Implemented on `fix/storie-issues` (2026-10-07), awaiting QA.
**SRS:** FR-12.1 in `docs/srs.md`

## Acceptance Criteria

1. Given the merged page, when I navigate to `/app/settings`, then all preference fields (currency, ghost threshold, reminders, name, data export/wipe/delete) are present in one place.
2. Given a visit to the old `/app/profile` URL, when loaded, then I am redirected to `/app/settings`.
3. Given the sidebar navigation, when viewed, then only one 'Settings' entry exists, not two.

## Dev Notes

- Product decision: merge into `/app/settings`, redirect the old `/app/profile` route. [Source: chat decision]

### Project Structure Notes

- Expected files:
  - `src/app/(main)/app/settings/page.tsx`
  - `src/app/(main)/app/profile/page.tsx`
  - `src/components/layout/sidebar.tsx`

### Architecture Compliance

- No API changes expected — both pages already hit the same backend route; this is a UI consolidation only.

### Testing Requirements

- Visit /app/profile, confirm redirect to /app/settings.
- Confirm every field previously on either page is present and functional on the merged page.

## Implementation Notes

- Settings is the base layout; Account block, Email and reminders section and Danger zone were ported from Profile.
- Export standardized on `/api/export` (no row cap, includes profile). The old capped export in Settings was removed.
- `/app/profile` is a server redirect to `/app/settings`. Sidebar avatar now links to Settings. The `p` shortcut was removed (`,` remains).
