# Story 12.4: Account Deletion — Settings, Profile & Notifications

## Story

As a user who wants to leave,
I want to permanently delete my account and all associated data,
so that my information isn't retained after I'm done with Traqit.

**Status:** ✅ Verified implemented on `main` (code-inspected).

## Acceptance Criteria

1. Given I confirm account deletion, when processed, then my Profile row and all cascaded data are permanently deleted.
2. Given `SUPABASE_SERVICE_ROLE_KEY` is configured, when account deletion runs, then the Supabase auth user is also deleted, not just the app-level Profile.

## Tasks / Subtasks

- [x] Verify existing deletion path
  - [x] Confirm `DELETE /api/profile` cascades correctly
  - [x] Confirm service-role auth-user deletion path, and graceful behavior if the key is absent

## Dependencies

**Prerequisites:** 12.1
**Blocks:** None.

## Dev Notes

- Unlike data wipe (12.3), this is intentionally permanent — account deletion is the one action that should NOT go through Trash, since the account itself is ending. [Source: `current-state.md#Features §11`]

- Expected files:
  - `src/app/api/profile/route.ts`

### Architecture Compliance

- Cascading delete via Prisma onDelete: Cascade on all Profile-owned relations.

### Testing Requirements

- Delete a test account, confirm all data is gone and the auth user is removed (if service role key is configured).
