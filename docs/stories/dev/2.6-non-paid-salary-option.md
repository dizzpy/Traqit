# Story 2.6: Non Paid Salary Option — Applications (Core Tracker)

## Story

As a user tracking unpaid internships or volunteer roles,
I want to mark an application's salary as 'Non-paid',
so that unpaid roles are distinct from applications where salary just wasn't disclosed.

**Status:** ✅ Implemented on `fix/storie-issues` (2026-10-07), awaiting QA.
**SRS:** FR-2.6 in `docs/srs.md`

## Acceptance Criteria

1. Given the Add/Edit form, when I select 'Non-paid', then the salary range inputs are disabled and cleared.
2. Given a Non-paid application, when viewed in the table, then the salary column shows a distinct 'Non-paid' label, not a blank cell.
3. Given an application with no salary entered at all, when viewed in the table, then it renders as blank/undisclosed and is never visually identical to Non-paid.

## Implementation Notes

- Column added with a targeted SQL file because `prisma db push` on the shared dev DB would drop 6 unrelated CV Studio tables. **Run `prisma/sql/add_application_is_non_paid.sql` on every other environment before deploy.**
- PATCH validation checks the merged state (payload + existing row), so a partial update can't create Non-paid + salary.
- Fixed alongside: `isNonPaid` was missing from the list API's select. Typing a salary into the table's inline cell on a Non-paid row clears the flag automatically.
- Detail panel has a "Mark non-paid" / "Set salary" toggle.
