# Story 12.3: Data Wipe Route Through Trash — Settings, Profile & Notifications

## Story

As a user who wants to start fresh,
I want wiping my application data to go through the same 30-day recovery as any other delete,
so that I don't lose everything permanently by clicking one button with no safety net.

**Status:** ✅ Implemented on `fix/storie-issues` (2026-10-07), awaiting QA.
**SRS:** FR-12.3 in `docs/srs.md`

## Acceptance Criteria

1. Given I trigger 'Wipe my data', when confirmed, then all my applications are soft-deleted (moved to Trash), not hard-deleted.
2. Given wiped applications sitting in Trash, when I check within 30 days, then I can restore them like any other deleted application.

## Tasks / Subtasks

- [x] Fix the wipe endpoint
  - [x] Change `DELETE /api/profile/data` from `prisma.application.deleteMany` to a soft-delete (`updateMany` setting `deletedAt`), matching the bulk-delete pattern in 2.4

## Dependencies

**Prerequisites:** 2.4, 11.1
**Blocks:** None.

## Dev Notes

- Product decision: no instant/permanent deletes anywhere except the final 30-day purge. This closes a known inconsistency where wipe bypassed Trash entirely. [Source: chat decision + `current-state.md#Known Issues`]

### Project Structure Notes

- Expected files:
  - `src/app/api/profile/data/route.ts`

### Architecture Compliance

- Reuses the same soft-delete pattern as bulk delete (2.4), just triggered from a different entry point.

### Testing Requirements

- Trigger wipe, confirm applications move to Trash (not gone), confirm restorable within 30 days.

## Implementation Notes

- `DELETE /api/profile/data` now soft-deletes (`deletedAt`), skipping rows already in Trash.
- Dialog copy changed from "permanently deleted" to "moved to Trash, restorable for 30 days".
