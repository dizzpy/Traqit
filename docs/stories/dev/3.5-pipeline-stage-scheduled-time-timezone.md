# Story 3.5: Pipeline Stage Scheduled Time and Timezone — Pipeline

## Story

As a student with interviews at specific times,
I want to set the time of a stage, not just the day,
so that my calendar and reminder emails match the actual interview time.

**Status:** ✅ Implemented on `fix/storie-issues` (2026-10-07), awaiting QA.
**SRS:** FR-3.5 in `docs/srs.md`

## Acceptance Criteria

1. Given a stage, when I set a date and a time, then both save and are shown in my local timezone after reload.
2. Given a stage with only a date (including every stage created before this story), when viewed, then it shows as all-day and nothing breaks.
3. Given my browser's timezone, when I use the app, then it is saved on my profile, and updated if it changes.
4. Given a timed stage and a 1-hour lead time, when the reminder check runs, then the reminder is sent about 1 hour before the stage's actual time (within the 15-minute check interval).
5. Given a timed stage, when shown on the Calendar and in the reminder email, then the time is shown in my timezone.

## Implementation Notes

- New columns: `PipelineStage.hasTime` (default false) and `Profile.timezone`. Applied via `prisma/sql/add_stage_time_and_profile_timezone.sql`. **Run it on every other environment before deploy.**
- Shared helpers in `src/lib/stage-time.ts` (client- and server-safe): `stageStart`, `stageLocalDay`, `stageLocalTime`, `stageDisplayDate`, `toStageSchedule`, and a DST-safe `zonedWallTimeToUtc` using `Intl`.
- UI: the stage date row in `pipeline-builder.tsx` gets an optional time box once a date is set. It saves on blur or Enter; clearing it makes the stage all-day. Changing the date keeps the time.
- `TimezoneSync` (`src/components/layout/timezone-sync.tsx`) in the app layout PATCHes the browser's timezone onto the profile only when it differs.
- Calendar shows `HH:mm` before timed events and in the agenda. All-day stages now land on the correct local day in every timezone (previously they could show a day early west of UTC).
- "Upcoming interview" badges on the list and board use the real start (09:00 local for all-day).
- Reminder check widens its DB window by a day either side, then filters on the exact start per stage. Emails show "Tue, Oct 14, 2026, 2:30 PM (Asia/Colombo)" for timed stages; UTC with a label if the timezone isn't known yet.
- `pipeline-stages.tsx` was not updated: it's dead code (not imported anywhere).
- Verified against the real dev DB: timezone maths incl. both US DST changes, browser helper round-trips (incl. a time that falls on the previous UTC day), stage PATCH storing/clearing `hasTime`, and reminder timing for timed (1h lead) and all-day (24h lead) stages in Asia/Colombo.
