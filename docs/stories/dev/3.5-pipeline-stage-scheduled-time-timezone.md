# Story 3.5: Pipeline Stage Scheduled Time and Timezone — Pipeline

## Story

As a student with interviews at specific times,
I want to set the time of a stage, not just the day,
so that my calendar and reminder emails match the actual interview time.

**Status:** ❌ Not started — new requirement from the SRS (2026-10-07).
**SRS:** FR-3.5 in `docs/srs.md`

## Acceptance Criteria

1. Given a stage, when I set a date and a time, then both save and are shown in my local timezone after reload.
2. Given a stage with only a date (including every stage created before this story), when viewed, then it shows as all-day and nothing breaks.
3. Given my browser's timezone, when I use the app, then it is saved on my profile, and updated if it changes.
4. Given a timed stage and a 1-hour lead time, when the reminder check runs, then the reminder is sent about 1 hour before the stage's actual time (within the 15-minute check interval).
5. Given a timed stage, when shown on the Calendar and in the reminder email, then the time is shown in my timezone.

## Tasks / Subtasks

- [ ] Schema
  - [ ] Add `Profile.timezone String?` (IANA name, e.g. `Asia/Colombo`) and a way to mark a stage as all-day vs timed (e.g. `PipelineStage.hasTime Boolean @default(false)`)
  - [ ] Ship as a `prisma/sql/*.sql` file, not `db push` (shared dev DB, see SRS G-3)
- [ ] Timezone capture
  - [ ] Detect `Intl.DateTimeFormat().resolvedOptions().timeZone` in the app shell and PATCH it to `/api/profile` when it differs
- [ ] Stage UI
  - [ ] Add an optional time input next to the date in `pipeline-stages.tsx` and `pipeline-builder.tsx`; send a full ISO timestamp when a time is set
  - [ ] Show the time on the Calendar (month cell and list view) for timed stages
- [ ] API
  - [ ] Stage routes accept a full timestamp plus the all-day flag; rescheduling still clears `reminderSentAt`
- [ ] Reminders
  - [ ] `runReminderCheck` uses the exact timestamp for timed stages; for all-day stages, treat the stage as starting at 09:00 in the user's timezone (decide and document)
  - [ ] Reminder email shows date + time in the user's timezone (fallback: UTC with a label)

## Dev Notes

- Today `scheduledDate` holds a date at 00:00 UTC. Keep the column; the new flag tells timed and all-day stages apart, so no data migration is needed.
- The all-day reminder anchor (suggested 09:00 local) is a product decision. Confirm before building.
- Timezone comes from the browser, not a Settings field (SRS assumption A-3).
