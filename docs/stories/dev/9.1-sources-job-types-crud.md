# Story 9.1: Sources Job Types Crud — Presets

## Story

As a job seeker,
I want to create, edit, and delete my own custom Sources and Job Types,
so that my dropdowns reflect terms that actually make sense for my search.

**Status:** ✅ Implemented on `fix/storie-issues` (2026-10-07), awaiting QA.
**SRS:** FR-9.1 in `docs/srs.md`

## Acceptance Criteria

1. Given the presets UI, when I add a new Source or Job Type, then it appears in the relevant dropdown immediately.
2. Given a duplicate name within the same profile, when I attempt to add it, then it's rejected (unique constraint).

## Verification Gap (found 2026-09-17)

Create+delete exist, but there is no edit route, and duplicate names silently upsert instead of being rejected as the AC requires. **Fix:** add an explicit PATCH route and a proper unique-violation error response.

## Implementation Notes

- POST now rejects duplicate names with 409 `DUPLICATE_NAME` instead of silently returning the existing row.
- Added `PATCH` (rename) to `/api/presets/sources/[id]` and `/api/presets/job-types/[id]`. Rename UI added 2026-10-07 (see below).
- Client helpers now surface API errors instead of ignoring them.
- Pre-QA follow-up (2026-10-07): Settings chips for sources and job types have a rename (pencil) button that edits in place; Enter/blur saves, Escape cancels, and a failed rename stays in edit mode with the error toasted.
- Renaming now also updates the user's applications that used the old name (`appliedVia` / `jobType`, Trash included) in the same transaction, so analytics don't split one source into two. Other users' data is untouched.
- Verified against the real dev DB: duplicate rename rejected with 409 and no change to applications; rename carried to active + trashed applications only for the owner; unknown id → 404.
