# QA: Story 8.2 — Ghost Detection Email Notification — QA Verification

**Epic:** Ghost Detection
**Traces to Dev Story:** 8.2-ghost-detection-email-notification.md
**SRS:** FR-8.2, FR-12.6 in `docs/srs.md`

### Setup Before Testing

- Set env `SMTP_HOST`, `SMTP_PORT`, `SMTP_USER`, `SMTP_PASS`, `EMAIL_FROM`, `CRON_SECRET`. Run `prisma/sql/add_notification_tracking_fields.sql`. Turn on "Email me about interviews and quiet applications" in Settings. To test without waiting for the schedule: `curl -X POST https://<app>/api/cron/ghost-check -H "Authorization: Bearer <CRON_SECRET>"`. To test the schedule itself, install `prisma/sql/pg_cron_notifications.sql`.

### Trigger Accuracy

- [ ] Only genuinely ghost-eligible applications trigger an email.
- [ ] An application that gets a response before the check runs does not get flagged.

### Duplicate Prevention

- [ ] Running the check twice in a row does not send two emails for the same application.

### Opt-Out Respected

- [ ] A user with reminders disabled receives no ghost emails.

### Email Content

- [ ] Email correctly identifies the company/position in question.
- [ ] Email renders correctly (not just as raw HTML/broken template) in at least Gmail and one other client.

### Behavior Details

- [ ] Eligibility matches the "Nd silent" badge: status Applied, no first response date, applied at least _threshold_ days ago.
- [ ] A user with several eligible applications gets **one** email listing all of them.
- [ ] Changing an already-notified application's applied date makes it eligible for a new email once it crosses the threshold again.
- [ ] Trashed applications are never included.
- [ ] Calling the route without the correct `Authorization` header returns 401; with SMTP unset it returns 503.

### Regression Sanity

- [ ] No console errors introduced in the browser during this flow.
- [ ] Data isolation holds — no other user's data is visible or affected.
- [ ] Feature behaves correctly on both desktop and a narrow (mobile-width) viewport, where applicable.
