# QA: Story 3.5 — Pipeline Stage Scheduled Time and Timezone — QA Verification

**Epic:** Pipeline
**Traces to Dev Story:** 3.5-pipeline-stage-scheduled-time-timezone.md
**SRS:** FR-3.5 in `docs/srs.md`

### Setup Before Testing

- Same email setup as QA 12.5, plus run `prisma/sql/add_stage_time_and_profile_timezone.sql`.

### Time Entry

- [ ] A stage can be given a date and a time; both persist after reload.
- [ ] Clearing the time makes the stage all-day again.
- [ ] Stages created before this change still display as all-day with no errors.

### Timezone

- [ ] The time shown matches the browser's timezone (test with the OS set to at least two different timezones).
- [ ] Changing the OS timezone and reloading updates the profile's timezone.

### Calendar

- [ ] Timed stages show their time in the month grid and the list view; all-day stages show no time.

### Reminders

- [ ] A timed stage with a 1-hour lead time is reminded about 1 hour before (within 15 minutes).
- [ ] The reminder email shows the stage's time in the user's timezone.
- [ ] Rescheduling the time after a reminder allows a new reminder.

### All-day Stages

- [ ] An all-day stage with a 24-hour lead time is reminded at about 09:00 local time the day before.
- [ ] An all-day stage's reminder email shows only the date, no time.
- [ ] The "upcoming interview" badge on the list and board appears within 48 hours of the stage's start (09:00 local for all-day).

### Regression Sanity

- [ ] No console errors introduced in the browser during this flow.
- [ ] Data isolation holds — no other user's data is visible or affected.
- [ ] Feature behaves correctly on both desktop and a narrow (mobile-width) viewport, where applicable.
