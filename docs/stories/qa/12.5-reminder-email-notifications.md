# QA: Story 12.5 — Reminder Email Notifications — QA Verification

**Epic:** Settings, Profile & Notifications
**Traces to Dev Story:** 12.5-reminder-email-notifications.md
**SRS:** FR-12.5, FR-12.6 in `docs/srs.md`

### Setup Before Testing

- Same as QA 8.2, but trigger `/api/cron/reminder-check`. Lead time counts back from the stage's start: its time if one is set, otherwise 09:00 in the user's timezone (e.g. an all-day stage on the 10th with a 24h lead time becomes due at 09:00 local on the 9th). Also run `prisma/sql/add_stage_time_and_profile_timezone.sql`.

### Trigger Accuracy

- [ ] Reminder sends at the correct lead time relative to the scheduled date, not early or late by more than the check's polling interval.
- [ ] Each lead-time option (1/3/24/48h) is tested at least once.

### Duplicate Prevention

- [ ] Running the check multiple times does not resend the same reminder.

### Opt-Out Respected

- [ ] A user with remindersEnabled=false receives no reminder emails.

### Email Content

- [ ] Email correctly identifies the company, position, stage and scheduled date, plus the time and timezone for timed stages (story 3.5).

### Behavior Details

- [ ] Rescheduling a stage that was already reminded allows a new reminder for the new date.
- [ ] Stages that are Done/Passed/Failed/Skipped get no reminder.
- [ ] Stages on Rejected or Withdrawn applications get no reminder.
- [ ] A stage whose date is already past gets no reminder.

### Regression Sanity

- [ ] No console errors introduced in the browser during this flow.
- [ ] Data isolation holds — no other user's data is visible or affected.
- [ ] Feature behaves correctly on both desktop and a narrow (mobile-width) viewport, where applicable.
