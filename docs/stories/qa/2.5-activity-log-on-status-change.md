# QA: Story 2.5 — Activity Log On Status Change — QA Verification

**Epic:** Applications (Core Tracker)
**Traces to Dev Story:** 2.5-activity-log-on-status-change.md

### Logging
- [ ] Every status change creates one Activity entry.
- [ ] Entry shows both old and new status.
- [ ] Timeline displays most-recent-first (or confirm intended order).

### Non-Status Edits
- [ ] Editing a non-status field (e.g. notes) does not create a spurious Activity entry, unless intentionally scoped to do so.

### Regression Sanity
- [ ] No console errors introduced in the browser during this flow.
- [ ] Data isolation holds — no other user's data is visible or affected.
- [ ] Feature behaves correctly on both desktop and a narrow (mobile-width) viewport, where applicable.
